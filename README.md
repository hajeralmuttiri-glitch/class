# مسابقة أنواع المخططات الستة 📊

منصة تفاعلية لمسابقة صفية: فرق تجيب على أسئلة، ترفع تصاميم من Canva، تصوّت، وتُعرض النتائج مباشرة أمام الطالبات، مع مزامنة فورية بين كل أجهزة الآيباد ولوحة المعلمة.

## 1) هيكل المشروع

جميع الملفات في نفس المستوى (بدون مجلدات فرعية) لتسهيل الرفع على GitHub:

```
index.html              → صفحة الطالبات (تُفتح على كل آيباد)
teacher.html             → لوحة المعلمة المحمية (تُعرض على البروجكتر)
style.css                → التصميم العام
data.js                  → الفرق + المراحل + أسئلة الفرق (عدّلي هنا فقط)
firebase-config.js       → إعدادات مشروع Firebase الخاص بك
firebase.js              → تهيئة Firebase (لا تحتاجين لتعديله)
student.js               → منطق صفحة الطالبات
teacher.js               → منطق لوحة المعلمة
team1.png ... team6.png  → صور المخططات
README.md
```

**طريقة الرفع:** حددي كل هذه الملفات دفعة وحدة من جهازك واسحبيها كلها مع بعض إلى صفحة "Upload files" في GitHub، ثم اضغطي Commit changes. لا حاجة لإنشاء أي مجلد.

## 2) لماذا Firebase؟

اخترتُ **Firebase Realtime Database + Firebase Storage** لأنها:
- مجانية تمامًا للاستخدام الصفي (Spark Plan).
- لا تحتاجين لكتابة أي كود خادم (Backend) منفصل.
- تعطي مزامنة فورية (Realtime) بين كل الأجهزة بدون أي إعداد إضافي — وهذا بالضبط ما تحتاجينه لعمل عدة آيباد في نفس الوقت.
- تخزين الصور المرفوعة من Canva عبر Firebase Storage بنفس الحساب.

## 3) إنشاء مشروع Firebase (مرة واحدة فقط)

1. اذهبي إلى https://console.firebase.google.com
2. اضغطي **Add project** → أعطيه أي اسم (مثلاً `chart-competition`) → أكملي الخطوات (يمكنك تعطيل Google Analytics).
3. من القائمة الجانبية: **Build → Realtime Database** → **Create Database** → اختاري أي منطقة قريبة → ابدئي في **وضع الاختبار (Test mode)** (سيُطلب لاحقًا ضبط القواعد، انظري القسم 4).
4. من القائمة الجانبية: **Build → Storage** → **Get started** → اتبعي نفس الخطوات (test mode).
5. من القائمة الجانبية: **Project settings (⚙️)** → في تبويب **General** انزلي إلى **Your apps** → اضغطي أيقونة الويب `</>` → أعطيه اسمًا → سجّلي التطبيق.
6. سيظهر لك كائن `firebaseConfig` يحتوي على `apiKey`, `authDomain`, `databaseURL`, إلخ.
7. انسخي هذه القيم والصقيها في ملف `js/firebase-config.js` بدلاً من `YOUR_...`.

> ملاحظة: تأكدي أن `databaseURL` منسوخ بالضبط كما يظهر في Firebase (يختلف الشكل حسب المنطقة).

## 4) قواعد الأمان (Rules) — بسيطة وكافية لهذا الاستخدام

بما أن الطلب هو تجنّب أي Backend منفصل، سنعتمد على قواعد بسيطة تسمح بالقراءة والكتابة خلال فترة الحصة فقط. في **Realtime Database → Rules** الصقي:

```json
{
  "rules": {
    ".read": true,
    ".write": true
  }
}
```

وفي **Storage → Rules**:

```
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /{allPaths=**} {
      allow read, write: if true;
    }
  }
}
```

⚠️ **تنبيه أمني بسيط:** هذه القواعد مفتوحة لأي شخص يعرف رابط قاعدة البيانات (وليس رابط الموقع فقط). هذا مقبول تمامًا لمسابقة صفية قصيرة المدة، لكن يُفضّل:
- عدم مشاركة رابط Firebase نفسه مع أحد.
- بعد انتهاء المسابقة، يمكنك تغيير القواعد إلى `false` مؤقتًا من نفس الصفحة لمنع أي كتابة جديدة.

## 5) التشغيل محليًا للتجربة

بما أن الملفات تستخدم `type="module"`، لا يعمل فتحها مباشرة بنقرتين (`file://`)، بل تحتاجين خادمًا محليًا بسيطًا:

```bash
cd chart-competition
python3 -m http.server 8000
```

ثم افتحي:
- الطالبات: `http://localhost:8000/index.html`
- المعلمة: `http://localhost:8000/teacher.html`

## 6) النشر على GitHub Pages

1. أنشئي مستودع (Repository) جديد على GitHub، مثلاً باسم `chart-competition`.
2. ارفعي كل محتويات مجلد `chart-competition/` إلى المستودع (عبر الموقع مباشرة بالسحب والإفلات، أو عبر Git).
3. من المستودع: **Settings → Pages**.
4. في **Source** اختاري **Deploy from a branch**، الفرع `main`، والمجلد `/ (root)` → **Save**.
5. انتظري دقيقة إلى دقيقتين، سيظهر لك رابط بالشكل:
   ```
   https://USERNAME.github.io/chart-competition/
   ```

### الروابط بعد النشر

- **رابط الطالبات (لكل آيباد):**
  `https://USERNAME.github.io/chart-competition/index.html`

- **رابط لوحة المعلمة (للبروجكتر):**
  `https://USERNAME.github.io/chart-competition/teacher.html`

## 7) حماية لوحة المعلمة عن الطالبات

- لوحة المعلمة محمية بكلمة مرور بسيطة معرّفة في `js/teacher.js`:
  ```js
  const TEACHER_PASSWORD = "chart2025";
  ```
  **غيّريها** إلى كلمة مرور خاصة بك قبل النشر.
- بعد إدخال كلمة المرور مرة واحدة، يتذكرها المتصفح طوال الجلسة (Session) على نفس الجهاز فقط.
- هذه حماية بسيطة مناسبة لصف دراسي (تمنع الطالبات من الدخول العرضي)، وليست حماية بمستوى بنكي. لا تشاركي رابط `teacher.html` مع الطالبات، واكتفي بمشاركة رابط `index.html` فقط معهن.

## 8) كيفية التحكم أثناء الحصة (النسخة المحدثة — 4 مراحل)

1. افتحي `teacher.html` وسجّلي الدخول بكلمة المرور.
2. اطلبي من كل فريق فتح `index.html` واختيار اسم فريقهم — لن يظهر لهم أي شيء غير شاشة الانتظار حتى تضغطي أنتِ.
3. اضغطي **"🚀 ابدأ المسابقة"** ليبدأ عد 120 ثانية للجميع في نفس اللحظة:
   - **المرحلة 1:** يكتبون تعريف مخطط المعلومات البياني تعاونيًا (يظهر لك مباشرة أثناء الكتابة).
   - **المرحلة 2:** يكتبون مزايا المخطط (120 ثانية أيضًا).
   - **المرحلة 3:** أسئلة أنواع المخططات الستة (اختيار من متعدد) — أضيفي نقاطًا يدويًا بزر "+".
   - **المرحلة 4:** يفتحون Canva، يصممون، يرفعون لقطة الشاشة (6 دقائق) — مع تحذير واضح لهم بعدم كتابة اسم الفريق.
4. اضغطي **"المرحلة التالية"** للانتقال إلى **معرض التصاميم والتصويت**: يولّد النظام رموزًا عشوائية (أ، ب، ج...) لكل فريق تلقائيًا حتى لا يعرف أحد صاحب التصميم، ويصوّت كل فريق لتصميم واحد غير تصميمه.
5. إذا لاحظتِ فريقًا كتب اسمه أو رمزه على التصميم، اضغطي **"استبعاد الفريق"** بجانب اسمه — يُستثنى فورًا من التصويت والفوز.
6. اضغطي **"احتساب وإعلان الفائز"** لعرض الفريق الأعلى تصويتًا (مع استثناء المستبعدين تلقائيًا).
7. **مهم:** المسابقة تُصفَّر تلقائيًا بعد **ساعة كاملة** من الضغط على "ابدأ المسابقة" (مناسب لتكرارها مع كل فصل) — أو اضغطي زر **"إعادة تصفير المسابقة بالكامل"** يدويًا في أي وقت لبدء فصل جديد فورًا.

⚠️ **ملاحظة عن التصفير التلقائي:** يعمل فقط طالما صفحة `teacher.html` مفتوحة في المتصفح (لأنه يعمل من داخل الصفحة نفسها). إذا أغلقتِ الصفحة، استخدمي زر التصفير اليدوي عند بداية كل حصة جديدة للتأكد.

## 9) إضافة أسئلة الفرق الستة لاحقًا

عندما تُرسلين الأسئلة (مع الصور)، سأقوم بتعديل ملف `js/data.js` فقط داخل الكائن `TEAM_QUESTIONS` — بنفس صياغتك تمامًا بدون أي تغيير، ووضع كل سؤال في مساحة فريقه المخصصة. لا حاجة لتعديل أي ملف آخر.

## 10) تحديث روابط Canva الخاصة بكل فريق

في نفس ملف `data.js` يوجد كائن اسمه `TEAM_CANVA_LINKS`. كل قيمة فيه حاليًا `https://www.canva.com` كرابط مؤقت. عندما تجهّزين رابط تصميم Canva الخاص بكل فريق (سواء رابط قالب جاهز أو ملف مشترك)، أرسلي لي الروابط الستة وبستبدلها لك، أو عدّليها بنفسك مباشرة داخل الكود بنفس الشكل:
```js
team1: "https://www.canva.com/design/xxxxx/edit",
```
